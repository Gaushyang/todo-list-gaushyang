> 適用網站：<https://gaushyang.netlify.app>  
> 建議放置位置：專案根目錄或 `docs/` 目錄  
> 文件用途：網站改善 Master Tracker、GitHub Issue 建立依據與驗收清單  
> 最後更新：2026-08-17

## 1. 改善目標

目前網站已有穩重的電信工程企業形象、清楚的服務定位與真實工程照片。下一階段的重點，是把網站從「企業形象展示」提升為可支援業務開發、客戶信任、人才招募與搜尋曝光的正式企業網站。

主要目標：

- 讓客戶快速了解高祥的工程能力、服務範圍與差異化優勢。
- 以專案實績、資格、工安制度與具體數據提高可信度。
- 縮短訪客從瀏覽到詢價、預約會勘的路徑。
- 補齊個資、SEO、無障礙、效能與品牌使用等基礎要求。
- 建立可以持續維護、量測與擴充的網站架構。

## 4. Issues 與 Action Items

### WEB-001｜綁定正式公司網域與正式上線設定

**優先級：** P0  
**目的：** 移除測試網站印象，建立正式、可信且可長期經營的公司網站入口。

#### Action Items

- [ ] 確認正式網域名稱與網域所有權。
- [ ] 將正式網域綁定至目前的部署服務。
- [ ] 啟用 HTTPS 並確認憑證可自動續期。
- [ ] 設定 `www` 與非 `www` 網域的唯一主版本及 301 轉址。
- [ ] 將 `netlify.app` 網址轉址至正式網域，避免重複內容。
- [ ] 更新網站內部連結、表單來源、canonical、sitemap 與分析工具設定。
- [ ] 設定公司網域信箱作為公開聯絡與表單寄件／收件地址。

#### 驗收標準

- 正式網域可使用 HTTPS 正常開啟，且無憑證警告。
- 所有其他網域版本均轉址至唯一正式網址。
- 網站沒有混合內容、失效連結或錯誤的 canonical。

## 8. 執行注意事項與歷史教訓

- **先補證據，再擴大宣傳：** 工程網站最常見的問題是服務很多、形容詞很多，但案例與驗收成果不足。優先補案例、資格與數據定義，能更直接提高信任。
- **避免品牌關係被誤讀：** 展示設備商或營運商 Logo 容易讓訪客推論為代理或正式合作。必須用精準文字界定實際關係。
- **正式網域不等於完成上線：** 網域切換時若忽略轉址、canonical、表單通知及搜尋設定，會造成重複內容、詢價遺失或搜尋排名重建。
- **不要為了蒐集名單增加過多欄位：** 表單越長，通常完成率越低。第一階段只取得聯絡與初步判斷所需資料，詳細需求可由業務後續確認。
- **數據必須可持續更新：** 累計站點、年資與團隊數量若沒有負責人和統計口徑，網站很快會出現過期或互相矛盾的資訊。
- **手機效能是工程客戶的實際情境：** 客戶或工程人員可能在現場以行動網路查看網站；圖片尺寸、載入速度與聯絡入口應優先以手機驗證。
